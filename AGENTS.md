# AGENTS.md — Latent Project Rules

> Rules and conventions for AI agents (and human contributors) working on this project.

---

## Project Context

- **Project name**: Latent
- **Origin**: Self-refinement of the CS5246 Text Mining final project (NUS)
- **Domain**: NLP pipeline for Reddit (r/Singapore) — scraping, preprocessing, clustering, sentiment analysis, search, and dashboard visualization
- **Primary languages**: Python (pipeline + backend), JavaScript/JSX (React frontend)

---

## General Rules

1. **Preserve existing comments and docstrings** — do not remove documentation that is unrelated to your changes.
2. **Follow existing code style** — match the conventions already used in the file you're editing.
3. **Do not commit intermediate data files** — CSVs, `.npz`, `.npy`, `.joblib` files are gitignored. Only code, configs, and dictionaries go in version control.
4. **Do not modify `utilities/singlish_dictionary.json` or `utilities/slang_dictionary.csv`** without explicit approval — these are hand-curated linguistic resources.

---

## Python Conventions

- **Python version**: 3.11+
- **Formatting**: Use 4-space indentation, follow PEP 8
- **Type hints**: Use type hints for function signatures (`def foo(x: str) -> int:`)
- **Logging**: Use `logging` module, not `print()`, for operational output in scripts
- **Imports**: Group by stdlib → third-party → local, separated by blank lines
- **Data paths**: Use `pathlib.Path` over `os.path` where practical
- **Docstrings**: Use triple-quoted docstrings for all public classes and functions
- **Dependencies**: When adding a new dependency, add it to the root `requirements.txt` and to `backend/requirements.txt` if it's backend-specific

---

## Notebook Conventions

- **Unified notebooks**: All notebooks reside directly in `notebooks/` with dual-environment auto-detection (local Jupyter & Google Colab)
- **Strip outputs before committing** — notebooks should not contain cell outputs in git
- **Each notebook must include**: (1) Open in Colab badge, (2) unified setup cell with auto-detect (`IN_COLAB = 'google.colab' in sys.modules`)
- **Use `scripts/convert_notebooks.py`** to sanitize and validate notebooks

---

## Frontend Conventions (Dashboard)

- **Framework**: React 19 + Vite 8 + Chakra UI 3
- **Directory**: `frontend/`
- **Styling**: Use Chakra UI components and theme tokens — avoid inline CSS where possible
- **Data layer**: All data flows through `DataProvider` context (`src/data/api.jsx`) — pages consume via `useData()` hook
- **API proxy**: Frontend proxies `/api/*` to Flask on port 5000 via Vite config
- **Charting**: Use Recharts for standard charts, Plotly for interactive/complex plots

---

## Backend Conventions (Flask API)

- **Directory**: `backend/`
- **Single entry point**: `backend/app.py` — all computation happens at startup, endpoints return pre-computed data
- **New endpoints**: Follow the pattern `@app.route('/api/<resource>')` and add to the `/api/all` response if needed
- **Data loading**: All CSV/model loading happens at module level (startup), not per-request
- **CLUSTER_LABELS dict**: Update this when re-clustering produces different groupings

---

## Git Conventions

- **Commit messages**: Use conventional commits format: `feat:`, `fix:`, `docs:`, `refactor:`, `chore:`
- **Branch naming**: `feature/<name>`, `fix/<name>`, `docs/<name>`
- **Never commit**: `.env`, `*.csv` (except dictionaries), `*.joblib`, `*.npy`, `*.npz`, `node_modules/`, `__pycache__/`

## Testing & Validation

- Before modifying pipeline stages, verify the output format matches what downstream stages expect
- The dashboard expects specific CSV column names — check `backend/app.py` for required columns
- Use `make lint` from root or in `frontend/` to check frontend code quality
- Use `python -m py_compile` to syntax-check Python modules
